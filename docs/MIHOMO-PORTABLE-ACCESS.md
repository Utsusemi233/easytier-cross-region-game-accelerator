# Clash 便携接入已有地区出口

这是一条可选的客户端接入方式：兼容的 Clash/Mihomo 客户端通过代理入口连接软路由，再复用软路由已有的地区出口。EasyTier、WireGuard 和 UDPspeeder 的部署方式仍见原部署文档。本项目的 `et-game apply` 不会自动部署这里的代理入口或公开接入网络。

## 接管和出口分别验证

游戏没有主动使用系统代理时，需要客户端自带的 TUN 将其请求送入核心。配置中的进程规则只决定已进入核心的流量如何选路。检查应用设置、核心 `/configs` 的实际 TUN 状态和游戏连接表，不能只检查 YAML 中的 `enable: true`。

目标路径为：客户端 → 接入软路由的认证代理 → 目标地区出口 → 应用服务器。地区出口的转发、源 NAT、返程和纠错链路需要单独验证。节点测速不代表这条完整路径的游戏延迟。

## 两种入口

IPv6 动态域名入口要求客户端网络能到达对应的 IPv6 服务。DDNS 更新入口地址，不能让没有 IPv6 的网络获得 IPv6 连通性。

另一种方式是使用 Mihomo 内置的 ZeroTier 出站作为认证代理的 `dialer-proxy`。客户端无需另装 ZeroTier 应用，但核心必须支持 `type: zerotier`。不能根据 Clash 前端名称判断支持情况，应使用实际核心进行语法检查和 TCP/UDP 验证。[Mihomo ZeroTier 文档](https://wiki.metacubex.one/config/proxies/zerotier/)

多设备分发时不要在文件中填写 `identity-secret`。让各设备生成并持久化自己的身份，由控制器分配不同虚拟地址。只复制配置文件，不复制其他设备的节点状态目录。`state-dir` 的默认身份保存行为和显式身份的覆盖规则见上游文档。

## 自动加入的边界

私有网络中的新身份通常需要授权。若希望同一文件在新设备自动加入，可单独建立限定用途的公开传输网络，并明确取得所有者对该范围的授权。网络 ID 的知晓者可以加入，代理仍须认证。原私人管理网络应保持独立。

控制器流量规则和路由器防火墙共同限制为：必要的 ARP、指定网关的认证 TCP/UDP 端口及对应回复。禁止客户端互访和管理服务，关闭普通广播，不提供默认路由或 LAN 转发。公开 ZeroTier 网络仍执行流量规则，但不能依靠成员撤销实现私网访问控制。[ZeroTier 协议说明](https://docs.zerotier.com/protocol/)、[流量规则](https://docs.zerotier.com/rules/)

`multicastLimit=0` 会影响需要组播的邻居发现。它表示一次组播最多发给多少个节点，不是总设备数上限。ARP 经过 ZeroTier 的专门处理，普通广播关闭时仍可工作。选取非零容量并验证实际数据；不要把增大数值当作降低游戏延迟的方法。

## 分流和 DIRECT

保留手动 `DIRECT` 的选择组。自动 `fallback`、`url-test` 或 `load-balance` 组只能引用代理节点，递归引用的子组也不能包含 `DIRECT`。两个入口都失败时应显示失败，不能悄悄改为直连。

在游戏进程和域名规则之后，可以加入适当的目标地区地址集合，补足只使用 IP 的请求。集合需要维护和覆盖检查。流量经过地区出口仍不等于应用一定更快，也不保证所有游戏服务器位于该集合。

## 验收清单

1. 对同一份文件分别运行两个独立的数据目录，核对不同身份和地址，并验证并发连接。
2. 分别验证认证代理的 TCP 和 UDP 实际出口。SOCKS 提前返回成功可能早于上游连接建立，不能单凭该响应判断管理端口已开放。
3. 使用实际数据检查允许的代理端口和禁止的管理端口；检查防火墙计数、持久化文件与服务启动状态。
4. 在一台实体电脑上启用 TUN，暂停可掩盖客户端问题的旧设备分流，验证目标地区出口和普通网络。
5. 进入游戏场景，核对游戏连接的规则、代理链和双向数据，再记录游戏内延迟。
6. 实测 Wi-Fi → 手机热点 → Wi-Fi，以及远端地址变化后的恢复。两个本机核心不能代替实体换网测试，服务启动状态不能代替完整重启测试。

持续连接的游戏会话可能需要重连。DDNS、邻居发现、P2P 协商、DNS 缓存和健康检查各有恢复时间，不能承诺任何国家、任何热点或零中断切换。若要直接接入地区出口，应另设独立名称和验收记录，不覆盖已工作的中转配置。

## 直接接入地区出口

直接版的业务路径是客户端 → 地区出口 → 应用服务器。已有接入网关可以继续作为另一份中转配置，但不能把它藏在直接版的候选节点或 `dialer-proxy` 中。普通 Wi-Fi 路由器承担上网转发，与另一个地区代理承担业务中转是两件事。

公网 IPv6 入口可省去打洞协商，但要求当前网络具备实际 IPv6 连通性。支持 Realm 的 Hysteria2 可以协商端点；协调注册成功仍需验证业务流量。使用同一地址、动态域名和节点名称，不代表两份配置走了相同的承载路径。

## 动态更新后的验证与回退

地址维护需要区分四项状态：新地址已观察、候选配置已校验、服务及监听已运行、外部业务已通过。状态面板和日志应分别报告，不能把前三项显示成“加速可用”。

本地地址观察可以采用短周期，不必每次向公共服务器测速。对稳定的新地址连续确认后，只更新项目拥有的监听或端点。使用匹配版本的核心校验候选配置，确认文件未被其他操作修改，再备份并原子替换。启动后检查实际服务和绑定地址；运行失败时仅回退自身改动。若当前配置已有新的并发修改，保留该修改并报告冲突。失败应退避，避免重复重启。

服务及监听检查是被动本地检查，不会产生跨境测速流量。外部 TCP、UDP 出口与游戏场景仍须单独测试；本地健康检查不能证明域名缓存已刷新或对端网络可达。

## 降低延迟和提高吞吐

先用不经过隧道的连接对照基础路径，再比较承载协议、纠错、MTU 和资源。如果普通建连也失败，关闭加密不能修复该阶段的失败。关闭 EasyTier 覆盖层加密需要两端一致配置，并在独立实验中验证；这个设置不等于移除 WireGuard 或 Hysteria2 所需的协议加密。[Mihomo EasyTier 参数](https://wiki.metacubex.one/config/proxies/easytier/)

纠错可能用额外带宽换取更可靠的交付，参数需要和持续传输一起比较。EasyTier 的 KCP/QUIC 代理针对 TCP 流，不能把启用它们直接写成游戏 UDP 已获得同样的纠错功能。[EasyTier KCP/QUIC 说明](https://easytier.cn/guide/network/kcp-proxy.html)

记录探测期限、实际回复数量、延迟分布和完整载荷吞吐。小样本超时率不直接等于物理丢包率；节点测速、链路应答与游戏延迟分别记录。未通过业务和恢复测试的直接版保留为实验，不替换已验证的中转版。
