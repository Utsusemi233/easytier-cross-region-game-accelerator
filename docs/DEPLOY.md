# 部署与失败处理

## 先检查

备份两端现有配置。安装上游luci-app-easytier及Lua兼容层，准备匹配架构的EasyTier core/cli与UDPspeeder V2。客户端需kmod-wireguard/wireguard-tools、fw4、nft、conntrack；家庭需kmod-tun、fw3/iptables、ip。不要从其他固件仓库强装内核包。

本项目不自动下载未校验二进制。用上游发布文件或你已验证的程序，填写实际路径。保持现有加速网络、WAN和WAN6；第一版不自动改无线频段、不删除SSID、不关闭IPv6。

## 安装插件文件

在OpenWrt SDK中将`openwrt/`目录作为包`luci-app-easytier-home-game`编译。手工安装源码用于测试时，按`scripts/install.sh`安装root/与luasrc/文件；先运行其预览，不替换系统网络配置。菜单依赖原luci-app-easytier。

从仓库下载源码归档，在路由器临时目录解压并进入项目目录，执行：

```sh
sh scripts/install.sh --plan
sh scripts/install.sh --install
```

安装脚本保留已有配置和原型服务，记录其余文件的安装备份，不在安装阶段改WAN/无线或启动全网代理。新增设备先读兼容性表：当前提供源码安装包，SDK生成IPK的流程尚未实际构建验收。修改接管模式的内层网段或端口需要独立迁移，不能直接套用到正在使用的原型。

升级会清理本扩展三个Lua模块的编译缓存，保留其他插件缓存。部分 LuCI 使用模块名的十六进制形式作为缓存文件名，不能用原模块名的文件通配符代替安装脚本中的清理步骤。若绕过安装脚本只复制源码，可能出现命令行是新版本、网页仍使用旧接口。

清理后仍有旧网页时，刷新浏览器以加载带版本号的资源；采用 uhttpd 的固件可从 SSH 重载管理网页服务。采用 nginx 的固件应按实际网页服务处理。管理网页重载不需要重启路由器或家庭隧道核心。

## 接管已有两地原型

执行`et-game adopt`填入已有线路的实际角色和发现配置，再`et-game doctor`。接管读取现有非敏感端点配置和实际FEC参数，关联已有codex-game服务；不重新生成WG私钥或EasyTier身份。随后`et-game plan`检查角色/网络/FEC/修改范围，`et-game apply`接入本扩展的监控及附加规则，`et-game verify`检查当前实际可用性。

进入VPN→EasyTier→跨地区游戏加速，可查看线路、执行检测、管理附加目的IPv4规则与设备范围、保存并应用配置。需要恢复时使用本插件生成的备份，保留原游戏和应用规则。

## 新设备部署顺序

1. 两台路由器分别填写`examples/home.uci`和`examples/client.uci`对应字段，两端FEC、端口和内层网段一致。家庭role=home，海外role=client，mode=managed。
2. 两端加入同一个获授权ZeroTier网络。填写对端固定节点ID、虚拟地址、虚拟MAC与实际虚拟接口；自动发现使用已知身份的全球IPv6路径。原生IPv6还必须实际可达。
3. 家庭先`et-game doctor`→`et-game plan`→`et-game apply`。应用只创建项目的服务/规则；入口UDP端口与已有服务冲突必须先解决。确认自己的家庭宽带允许出口NAT。
4. 从家庭生成配对资料。配对文件可能含WG客户端私钥，只能经你控制的渠道传到海外路由器，不放GitHub、不贴诊断日志。客户端导入后指定不冲突的内层IP、现有游戏网络和规则范围。
5. 客户端`et-game plan`→`et-game apply`→`et-game verify`。不通过时先检查对应失败项，不以“看见进程”为成功；采用本地路线，不强迫所有应用走不可用家庭出口。
6. 测试同一游戏退出重进后的延迟，普通SSID与海外网站，再完成动态地址/入口故障对照。[验收流程](ACCEPTANCE.md)中未实际执行的项目必须保留“未测试”。

配对命令（在你私下传输后删除临时配对文件）：

```sh
# 家庭
et-game export-profile /tmp/home-game.private.pair.json
# 海外
et-game import-profile /tmp/home-game.private.pair.json
```

第一版验证的是一对家庭/海外网关。不要把同一客户端身份和地址不加检查地复制给多个海外网关；多网关节点隔离与独立地址需单独验证。

## 规则与参数

附加规则按现有加速网络或单一设备IPv4范围、目的IPv4 CIDR、TCP/UDP和目的端口选择，其他流量本地走。既有游戏国内UDP集合、应用DNS与MSS规则仍是独立功能，不把旧规则隐藏成新面板生成的规则。

在“加速规则”中添加或编辑后先完成编辑。仅保存会保留当前运行规则；保存并应用会先重新读取核对存储内容，再加载和验证。主机地址自动补 `/32`；带主机位的网段会按实际网络地址生成规则。无效地址、越出加速网络的设备或不合法端口显示字段错误，不提交运行修改。

查看每条规则的运行证据：待应用表示存储尚未部署，已加载表示实际条件通过核对，已命中表示有匹配包。已命中时还需当前家庭出口与策略路由可用；故障回退不显示成家庭加速。删除或停用后再次保存并应用，并检查没有残留或重复规则提示。出现异常时可重新应用；应用失败会尝试从本次备份恢复，并明确报告是否恢复成功。

新规则首次生效后应退出并重开相关应用，使其建立新连接。测试时确认设备确实在加速网络内，避免另一条网线或移动数据影响对照。规则列表计数不是完整带宽统计，也不能代替应用效果测量。

全新安装不会自动识别所有游戏和行情软件：需要提供真实目的IPv4/端口规则。先在同一游戏登录和场景连接中观察目的服务器，再以窄规则做关/开对照；文档的203.0.113.0/24及2001:db8::/32只是不可用于真实公网的示例地址。应用DNS域名自动更新与目的IPv6流量分流尚不在这一版面板的新增规则功能内。

FEC必须两端匹配。高冗余先确认带宽成本；改本地不会自动代替你改对端。家庭配对资料携带参数，用作核对。两端不一致时不要验收。

## 诊断、停用和恢复

`et-game status`读取状态；`et-game doctor`检查依赖与配置；`et-game verify`主动验证；`et-game pause`暂停家庭分流；`et-game resume`重新验证后恢复；`et-game backup`保存本项目所管理文件；`et-game rollback BACKUP_ID`按备份恢复自身文件，不覆盖其他人后来修改的整个firewall/network配置。

动态发现没有新路径、WAN6没有全球地址、HTTPS出口验证失败或验证过期时，应清楚显示失败并使用本地出口。额外远端入口、纯IPv4回落、整机重启后的真实新前缀恢复均需另外验证。
