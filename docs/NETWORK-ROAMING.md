# 更换 Wi-Fi、热点与实际 IP

电脑接入的目标是：换到另一个可用网络后，继续使用同一份私人配置，自动恢复连接，无需用户手填新的局域网或公网 IP。提供可选的 Windows 后台维护组件，面向“官方客户端 → 自有 ZeroTier → 已有原生网关”的 IPv4 接入模式。它维护底层路线并验证入口，保留官方 GUI；不是覆盖任意网络条件的通用加速器。

## 分清三种地址变化

| 地址 | 由谁处理 | 需要验证什么 |
| --- | --- | --- |
| 电脑 Wi-Fi、热点或网线的实际地址和网关 | 操作系统、官方客户端及所用底层网络 | 换网后连接与底层绕行使用当前可用接口，不继续指向旧网关 |
| EasyTier 虚拟 IPv4 | 官方客户端；新设备模板使用 DHCP | 地址不冲突；它不必随 Wi-Fi 的实际 IP 一起变化，也不代表已经恢复出网 |
| 远端出口或既有纠错端点的公网地址 | 对应入口发现机制或路由器端点模块 | 新地址可达、隧道与出口通过当前验证后才恢复所选路线 |

不能把客户端 DHCP 或家庭端 IPv6 更新，当作电脑换网后的路由恢复已经完成。固定的虚拟地址也不等于电脑必须固定公网 IP。

## 先确认外出路径

电脑直接连接授权原生出口时，需要从新网络可达的匹配入口。电脑复用已有纠错网关时，需要先从新网络访问那个网关，再使用其原后端；局域网监听地址不会自行变成公网入口。若借助自有 ZeroTier 私网访问网关，须完成新节点授权并检查底层连接。保留原有凭据，无需因换热点重新创建私网。

不要把当前 Wi-Fi 的接口编号、源 IP 或默认网关写成永久前提。没有固定绑定只是配置检查结果，不能单独证明运行中的程序能正确处理换网。若监听或绑定确有要求，应说明其用途并实测切换。

## 路由与恢复要求

1. 启用选定范围或两段 `/1` 前，记录当前物理接口、默认网关、入口和底层路径，以及本项目添加的绕行路线。凭据和地址只保存在私人记录中。
2. 换网后重新读取实际接口、网关及需要绕行的端点。入口与底层连接必须走当前可用网络，不能被 EasyTier 的全 IPv4 路由送回自身。
3. 只有能确认归属本项目的旧路线才可清理；对应绕行随新网关恢复，不保留无效旧网卡路线，也不清空其他 VPN、DNS 或系统路由。
4. 先验证当前 peer 路径，再验证真实 TUN、所选出口 HTTPS、应用流量和普通网络。区分直连、中继与断开。记录网络恢复和出口验证分别耗时多少，不承诺固定恢复秒数。
5. 断开、重连与停止时按接入模式恢复普通出网并释放自身路线；实际回退结果需要验证，不能用路由器后端的回退代替电脑端检查。

优先使用官方客户端和已有组件。需要本机动态路线维护时，可明确选用下面的后台组件，保留官方 GUI，不制作替代连接界面或包装程序。当前组件只覆盖所列网关模式；其他结构缺少自动恢复时应明确报告，不能要求用户固定热点 IP 后把移动接入标为通过。

## 实际换网验收

| 测试 | 通过条件 |
| --- | --- |
| 当前 Wi-Fi → 手机热点 | 不改 TOML、凭据或虚拟地址，底层改走当前物理网络，真实出口恢复 |
| 手机热点 → 原 Wi-Fi | 再次恢复，没有残留死路线或重复规则 |
| DHCP 更新、网关或物理接口变化 | 读取新网络参数，绕行不依赖旧参数；未实测的变化分别标注 |
| IPv4-only 外部网络 | 按此模式真实验证；电脑入口能用 IPv4 不等于路由器 FEC 后端已支持纯 IPv4 |
| 短暂断网、停止与重开 | 普通出网及本项目路线释放/恢复符合所选模式，恢复时间有记录 |
| 应用新连接 | 重新建立连接后检查流量；不要求游戏会话跨网络无缝保活 |

每项报告 `passed / failed / skipped`，并写出当前能力来自哪个组件。只有配置解析、DHCP 分配或同一局域网可用时，移动接入仍未通过。

热点需要网页登录或限制 UDP 时，应先区分网络限制与本项目配置故障。ZeroTier 官方说明指出，受限网络可能采用中继，连接可用性与最佳性能是不同条件。不能由“实际 IP 可以变化”推导出“任何热点都保证连接或保持相同延迟”。[ZeroTier 网络条件说明](https://docs.zerotier.com/routertips/)


## 安装可选 Windows 网络恢复组件

地点本身不限制共享配置，但接入网络必须能到达已授权入口。受限 UDP、运营商 NAT、中继和入口离线都可能影响连通或延迟；不同国家、运营商和热点应分别验收。复用另一地区的策略网关会多一段路径，距离越远未必越快。组件自动更新路线，不会自动选择全球最低延迟出口。

需要 Windows PowerShell 5.1、系统 curl.exe、管理员安装权限、官方 EasyTier GUI、已授权且可达的自有 ZeroTier 网络，以及原生网关。网关监听与私网入站规则必须同时有效；只绑定私网地址、不放行对应 UDP/TCP 端口，外出仍无法接入。

把 [windows/](../windows/) 保存到稳定目录，按 [roaming.example.json](../windows/roaming.example.json) 私下填写实际 TUN 名称、网关虚拟地址、状态目录和路由度量。组件只维护明确配置的两条 `/1` 和自身创建/明确接管的底层主机路线，不克隆 ZeroTier 身份，不更新官方 TOML。

```powershell
# 先检查计划；下面为示例路径。
.\Install-NetworkRoaming.ps1 -ConfigPath E:\EasyTier\private\network-roaming.private.json
# 在管理员终端明确安装后台任务。
.\Install-NetworkRoaming.ps1 -ConfigPath E:\EasyTier\private\network-roaming.private.json -Apply
# 读取私人状态，不把它上传到公共 Issue。
Get-Content E:\EasyTier\private\roaming-state\status.private.json
```

任务监听网卡配置事件，另有可配置轮询。它从本机 ZeroTier 服务读取已认证路径，按当前 IPv4 接口/网关维护底层绕行。地址或网关变化时先撤下所管理的全 IPv4 路线；实际虚拟网关探测与明确使用 IPv4 的 HTTPS 通过后恢复。两次网关探测失败会回退。IPv6 临时地址变化不触发无关的 IPv4 路线撤换，家庭端 IPv6 继续由原路由器模块处理。

状态 `entry_verified` 只表示本机原生网关和普通互联网验证通过，家庭纠错出口仍由路由器独立验证。`entry_degraded` 表示一次网关探测失败、暂留路线等待复核；`local_fallback` 表示撤下所管理的加速路线；切换物理网络本身断网时，不能保证普通互联网同时可用。轮询间隔不是保证恢复时间，也不保证现有游戏会话不断线。

停止使用时运行同一安装脚本的 `-Remove`：只移除匹配任务及所管理路线，保留官方客户端和其他 VPN。之后如需恢复原官方完整路由，按原配置在官方界面停用后重新运行。当前组件要求有可用的物理 IPv4 网关；IPv6-only 接入、其他 VPN 接管物理路径和多网卡优先级需另行适配/验收。路线规划隔离测试见 `tests/windows-roaming.ps1`，真实不同网络与开机恢复仍应在各自设备验收。
