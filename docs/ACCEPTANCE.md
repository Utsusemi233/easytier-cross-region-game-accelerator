# 验收方法

本文件提供检查方法，不包含任何所有者的个人测试结果。测量应保存在部署者自己的私人记录中；公开反馈请去除网络身份、地址、账号和可识别截图。

## OpenWrt 网关部署验收

下表针对当前 WireGuard + UDPspeeder 网关链路。电脑直连原生出口按[电脑接入说明](WINDOWS-TRAVEL.md)验收；电脑复用已有纠错网关则按[原生网关接入](NATIVE-GATEWAY.md)同时检查新增接入与原后端。Linux 主机或 NAS 出口的部署尚需独立验证，不能仅凭本表的方法认定仓库已支持自动部署。

| 检查 | 如何判定 |
| --- | --- |
| 当前端点与身份 | 实际WAN全球IPv6；仅固定对端节点发现；拒绝其他节点和过期路径 |
| 验证门控 | 当前签名相符，验证时间未过期，缺失/旧结果不得维持home |
| 隧道 | 固定WG诊断源主动探测，统计丢包与RTT，不采用接口UP代替 |
| 家庭互联网 | 固定WG源的HTTPS请求成功；与本地出口分开验证 |
| 普通网络 | 普通SSID/本地HTTPS仍可用，加速网络非所选流量仍本地 |
| IPv6与应用 | 已验证的IPv6 relay及既有应用DNS/MSS不被删除 |
| 源地址变化 | 选另一条实际已分配地址或由运营商换址；记录发现及恢复时间 |
| 对端故障 | 停一个FEC入口，确认direct或其他有效入口，不留死路由 |
| 服务恢复 | 同地址重启监控、确认不反复重启核心并重新完成验证 |
| 开机恢复 | 真实重启后验证；只检查enabled不能标成开机实测通过 |
| 带宽成本 | 同一时段WG与FEC计数变化、参数、时长；计数重置必须标为无效 |
| 应用体验 | 同设备/游戏/服务器/场景，关→开对照，并记录时间和丢包波动 |

报告使用passed/failed/skipped。只因当前验证全部passed就宣称不同固件、纯IPv4、运营商前缀重拨、长期稳定性均完成，是不合格的报告。

## 新增原生网关接入

先验证共享网络身份和客户端地址分配，再检查实际 TUN、Windows 路由、新入接口的分类和返程。原网关可能只允许自己的 WG 源，必须核对新增网段的允许范围或源 NAT。海外 HTTPS 和原 IPv6 也应实际可用。

停用、重开、防火墙重载分别验证：停用后自身规则释放，重载后有效配置恢复，停用状态下重载不会又加回规则。自定义 WAN/ZeroTier 事件应唤醒监测，新端点仍需当前验证成功。

官方 `--check-config` 通过只表示配置能解析。两实例 `--no-tun` 的不同地址只表示可以分配；另一台电脑的实际网卡、出口和游戏必须另测。源/收发计数因重启重置后，不用前后累计值判断性能改善。

## 电脑移动接入验收

按 [NETWORK-ROAMING.md](NETWORK-ROAMING.md)执行真实 Wi-Fi → 手机热点 → 原 Wi-Fi 对照，保持同一份连接配置，不要求固定物理 IP。每次切换核对当前接口/网关、底层绕行、旧路线清理、peer 路径、实际 TUN、所选出口与普通网络，记录恢复用时。应用重新建立连接后再测，不把会话无缝保活作为已实现能力。

虚拟 DHCP、远端 IPv6 更新和电脑物理网络恢复分别报告。未固定绑定、程序存在或局域网成功不能替代换网验证。短暂断网、IPv4-only、网关变化和启停未实测时标 `skipped`；使用可选 Windows 组件时，同时核对任务、最近状态和实际路线；该组件未覆盖的结构仍需适配，缺项不能标 `passed`。
