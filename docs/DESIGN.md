# LuCI 面板设计与规则反馈

面板继承现有 LuCI 主题，明确区分草稿、保存、应用和真实运行状态。

## 设计依据

阅读并使用以下技能：

- [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)：先明确结构，再实现并用截图复查。
- [Vercel web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines)：表单标签、键盘、异步反馈、错误定位和主题适配。
- [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)：加载按钮与可聚焦错误摘要的本地搜索结果适用于本项目。

通用设计系统搜索返回的营销首屏、玻璃效果和外部字体不符合路由器后台。本项目以现有 LuCI 为样式来源，沿用字体、主色、表单行、按钮和页签。不引入外部字体、React、Tailwind 或额外服务。

## 布局

```
EasyTier 原有顶层导航
跨地区游戏加速
运行状态 | 加速规则 | 线路设置 | 诊断
当前操作结果（操作后可见）
当前页签内容
修改状态                 保存 / 保存并应用
```

页面内容左对齐。状态区采用线路摘要和两列表格，不使用三张独立大数字卡。规则列表只展示核心信息；编辑在独立表单内完成，手机不需要横向滚动。高级端点与配对放在线路设置下，家庭角色不显示客户端规则操作。

颜色由 LuCI 的文字、边框、背景和主色继承；仅成功、警告、失败使用固定语义色，并同时展示文字。字号继承原后台，手机输入不小于16px。输入标签始终可见；手机操作按钮高度至少44px，手机页签排为两列。无自动播放动画，焦点清楚，页签支持键盘与 URL hash。

## 操作契约

1. 编辑仅改变草稿，显示“有未保存修改”；轮询不覆盖草稿。
2. 保存后重新读取服务器，核对配置和规则；保存不声明运行生效。
3. 保存并应用依次保存、应用，再检查实际加载和当前出口。超时必须显示“尚未确认”，不能显示成功。
4. 每条运行规则以独立标识关联 nftables 规则、表达式和计数。保存、已加载、命中三个状态分别显示。
5. 已加载但无计数只说明尚无匹配包；计数增加证明匹配发生，不等于游戏一定更快。当前家庭出口和策略路由另外检查。
6. 暂停或故障时展示本地回退；已命中规则也不能显示为家庭加速中。
7. 无效输入在字段旁说明，提交时聚焦错误摘要。错误保留输入，不能静默清空。
8. 正在执行期间防止重复提交，显示操作名称与经过时间；断网、登录失效和服务拒绝分别说明。
9. 家庭导出与海外导入仅在相应角色出现。配对错误在当前页反馈；文件不在浏览器存储。
10. 操作历史记录最近操作及结果，不在每次状态轮询时覆盖。
11. 运行链中出现重复、多余或删除后残留的规则时，整体核验失败并显示数量；不能只核验列表中仍存在的规则。
12. 错误摘要链接定位到高级字段时自动展开所属区域；不让焦点落到隐藏控件。

## 验收

本地 Lua5.1/ES5 检查；真实网页增删改规则、保存重载、应用后实际 nft 表达式/计数、禁用规则移除、失败字段反馈、暂停恢复、无输入丢失、两端角色和桌面/手机截图。应用体验与界面验收分别记录。
