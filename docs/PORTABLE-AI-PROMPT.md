# 交给官方电脑客户端部署的 AI

下面以 Windows 电脑连接国内授权出口为例。提示词不包含出口密钥；使用者须另外通过私人文件或可信渠道提供连接资料，不要上传到公共仓库或直接贴进公共Issue。

先选择电脑直接连接原生出口，或接入已有 OpenWrt 纠错网关。直接路径不要求本地 OpenWrt；已有网关路径需要匹配入口与新增来源的分类/返程。OpenWrt 主部署仍走[网关部署文档](DEPLOY.md)。

```text
请阅读 https://github.com/Utsusemi233/easytier-cross-region-game-accelerator 的AGENTS.md、README.md、docs/WINDOWS-TRAVEL.md、docs/NETWORK-ROAMING.md和兼容性说明。先确认我选的是电脑直连原生出口，还是电脑接入已有OpenWrt纠错网关；后者再读docs/NATIVE-GATEWAY.md和docs/DEPLOYMENT-LESSONS.md。在这台Windows电脑的独立目录安装并配置官方EasyTier，让我不用手填参数。保留已有效的两端线路，检查实际平台和协议；OpenWrt自动部署步骤不直接用于电脑、Linux主机或NAS。新增原生桥接是手工集成参考，不声称安装脚本会自动完成。

我会私下提供授权出口的原生EasyTier连接资料（网络名称、network_secret、出口虚拟IPv4、可用入口及共享发现节点），或让你从我授权的已配置电脑读取。路由器的WireGuard配对JSON不能直接当作EasyTier原生配置。

请先检查本机系统/架构、管理员权限、已有VPN、网卡、路由及服务，从官网选择与出口端兼容的官方 EasyTier GUI 发布版并校验官方 SHA-256。使用本机独立安装目录，把桌面快捷方式直接指向官方 easytier-gui.exe，通过官方界面导入和保存私人配置。不要制作自定义连接界面、替代程序或连接脚本快捷方式。

同一EasyTier私网使用一致的network_name/network_secret。在匹配的2.6.4配置中，优先省略instance_id/ipv4并设置dhcp=true，让官方程序自动生成本地实例标识和分配未冲突虚拟IPv4。多台获授权电脑可导入同一份已填好的私人配置，不要求我手填独立身份或地址。先确认入口在线，分配后读回实际地址。不要把原电脑固定地址恢复文件作为多机模板，也不要复制WireGuard/ZeroTier整机身份。

我的移动接入要求是：更换Wi-Fi、手机热点、局域网或公网IP后，继续使用同一份配置并自动恢复，无需我手改地址、网关、账号或虚拟IP。区分电脑实际网络变化、EasyTier虚拟DHCP、远端公网端点更新，不能用其中一项通过代替其他两项。不要把当前接口编号、源IP或默认网关写成永久前提；未固定绑定也不等于已经验证自动重连。局域网入口不能作为唯一外出入口。复用已有网关时说明远程入口与授权方式，两端网关继续在线；直接原生出口按其实际可达方式检查。

直连模式配置授权exit node和选定IPv4范围。接已有网关模式由客户端把IPv4交给网关，再复用已有目标/UDP分类、策略路由和源NAT，其余在网关走当地出口。先检查原集合、端口排除、WG允许的来源、DNS重定向与重载恢复；特定App TCP/DNS规则不自动全部继承。TOML字段是routes；若采用两段/1，必须检查底层承载有绕行路线。区域IPv4分配记录不是应用自动识别。保留原DNS/IPv6和无关VPN，先验证真实目标，再启用实际所需范围。

核对底层入口和ZeroTier等承载没有被完整IPv4路线捕获。换网后应使用新物理接口、当前默认网关和有效端点，清理能确认归属本项目的失效旧绕行路线，保留其他VPN和系统路由。优先用官方客户端、官方服务模式和已有组件完成恢复，不增加自制UI或包装程序；我要求自动换网恢复时，可按NETWORK-ROAMING.md显式部署本仓库windows/后台组件，检查计划、配置、任务与实际状态，不另造替代客户端。若当前结构尚不能自动维护必要路线，列出具体缺项；不要让用户固定热点IP来替代修复，也不要把待实现方案写成已经完成。

在必要的Windows管理员确认后自动完成配置，用官方客户端的运行、停止和托盘入口操作；如启用开机恢复，使用官方服务模式并验证。记录修改前后配置并准备仅撤销自身更改的恢复方式。不要未经检查修改出口端原有服务、无线、纠错参数或系统默认路由。

验证peer、实际TUN路线、真实场景UDP、网关规则与双向NAT、选定出口HTTPS和普通网络。直接原生路径不自带UDPspeeder；已有网关模式复用路由器FEC后端。公网地址变化由已部署的路由器端点模块处理，客户端DHCP是另外一项功能。验证停用释放、重开和防火墙重载；另一台实体机器、热点/酒店、IPv4-only和整体换前缀没有条件时标未测试。两实例无TUN检查只验地址分配。不要从“已连接”或一条登录TCP推断实际场景已加速，也不承诺固定延迟。

将真实换网单独验收：当前Wi-Fi→手机热点→原Wi-Fi，全程不改连接配置；核对peer直连/中继、实际TUN、底层新网关、所选出口HTTPS、普通网络和新建应用连接，记录恢复用时。再分别测试短暂断网、停止/重开、IPv4-only与DHCP/网关变化；没有条件的项目标未测试。不要声称游戏会话跨网无缝保活，受限热点也不能承诺必连或保持相同延迟。仅配置解析、虚拟DHCP或局域网成功，不算外出验收。

完成后告诉我安装路径、日常连接方法、通过/失败/未测试项目，以及本机恢复方法。密钥和私人连接资料禁止写入公开GitHub、公开报告或诊断截图；只有另获所有者明确授权的私有仓库可保存私人部署资料。
```


## 可选直连提示

需要电脑直接连接授权出口时，阅读 DIRECT-HOME.md 和 manual/。在官方 GUI 上配置本机纠错入口与真实出口，不把原访问网关设为必经节点。先部署并验证家庭原生入口、逐 IPv6 纠错监听、源 NAT 和持久化，再安装自己的 Windows 维护任务。保留旧配置、原网关线路和归属日志。用当前网关与绑定 TUN 源的 IPv4 HTTPS 核查，完成入口失效、全部失败、恢复、GUI 停启和不同网络的测试。地址轮询不是总恢复时间保证。无法完成的设备/网络测试明确写 SKIPPED。
