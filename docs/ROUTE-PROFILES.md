# 保留直连，增加经已有网关的配置

换到手机热点后，远端仍在线，但直连延迟可能变高。先分别测本地网关、远端公网地址、虚拟网关和实际应用。当地网络快、跨境公网路径慢时，增加纠错不能替代路由选择。可保留直连配置，再测试经另一台自有网关到相同出口的路径。

## 两种路径分别保存

| 配置 | 实际路径 | 依赖 |
| --- | --- | --- |
| Region-Direct | 官方客户端、本机 UDPspeeder、授权地区出口 | 出口原生 EasyTier/FEC、授权地址发现 |
| Region-via-Gateway | 官方客户端、自有网关、该网关的既有分流和纠错后端、授权地区出口 | 可达的网关原生入口、网关与出口都在线 |

中转可能绕开一条较差的跨境路径，也可能增加延迟。必须测完整链路，不能拿客户端到第一台网关的延迟当作应用延迟。私网入口显示 P2P，也不能据此判断承载私网是否经过中继。

两种配置保留不同的 TUN 名称。一次只运行一种：先在官方 GUI 禁用当前网络，再选择另一项并运行。不要把两个重叠的虚拟网段和地区路由同时启用。新设备继续使用获授权的 DHCP 模板；共享网络凭据不等于复制固定地址或底层设备身份。

## 名称也是配对参数

官方 GUI 的“网络名称”对应 `network_identity.network_name`，参与建立 EasyTier 私网。它不是单纯的备注。只改客户端，入口仍使用原名，会造成身份不一致，节点连接可能失败。不同路径可使用清楚的配对名称，但每条路径的客户端与入口必须同步。

更名步骤：保存两端原配置，核对该原生入口的在线客户端范围，停止对应客户端，同步两端名称，保留密钥、端口与转发规则，检查 TOML，再只重启这条原生入口和客户端。原生接入服务与已有 WireGuard 游戏后台应分开。共享入口有其他客户端时，应协调更新，不把更名当成没有影响的文字编辑。

## 为新增网关配置维护地区路线

原有网关的 `/1` 接入模式仍按 [NATIVE-GATEWAY.md](NATIVE-GATEWAY.md) 使用。另一个可选方式是：官方配置只声明虚拟网段，由 Windows 维护组件在验证后加入选定地区 IPv4 路线。未选定目的继续用物理网络。

1. 使用 [原生 DHCP 客户端模板](../examples/native-client.auto.toml)，替换自己的入口、共享配对信息和虚拟网关。移除其中两段 `/1`，保留实际虚拟网段，设置独立 TUN 名称。
2. 填写 [网关维护示例](../windows/native-gateway.example.json)。`prefixes_file` 是已审核的 IPv4 CIDR 数组；配置自己的 HTTPS 探测地址和证书域名。示例地址仅用于展示格式。
3. 先运行 `Install-NativeGatewayRecovery.ps1 -ConfigPath <私人配置>` 查看范围，再以管理员加 `-Apply` 显式安装。脚本与 `Direct-HomeRecovery.ps1`、其辅助文件应放在同一目录。安装组件不会代替安装官方 GUI、授权底层私网或部署网关。
4. 维护组件检测物理 IPv4/IPv6、网关、TUN 接口和虚拟地址；变化时清除原证明并撤下自身路线。底层当前 IPv4 端点按归属记录绕行。成功的虚拟网关 ICMP与指定 TUN 源的 IPv4 HTTPS共同建立验证；失败不延长成功时间，证明到期后回退当地网络。
5. `conflicting_tunnel_aliases` 可列出互斥配置。冲突时本组件停止加入自己的地区路线。这不是官方 GUI 的全局互斥开关，用户仍应先禁用原网络，再启用另一个。

状态文件中的网关/HTTPS验证只描述电脑到接入网关的数据路径。网关到最终地区出口仍须独立执行 `et-game verify`，核对实际分类、策略表、出口 NAT与流量。已有 UDP规则不会自动覆盖所有 TCP、DNS、下载或目的 IPv6。

## 验收与恢复

保留更名前后的配置、官方编辑器读回、真实系统路线、底层路径和后端计数。分别测网关入口、完整回国链路、游戏场景及普通网站。实际执行配置停启和热点断开重连；未执行的其他运营商、国家、前缀委派或第二设备测试应明确保留。

移除新增维护组件用 `Install-NativeGatewayRecovery.ps1 -ConfigPath <私人配置> -Remove`，再禁用对应官方网络。仅删除自己的任务和路线，不重置系统网络，也不覆盖旧直连配置。

## 从目标地区经海外出口访问网络

反向使用需要第三个独立配置：由目标地区客户端接入获授权的海外互联网出口，采用对应的目的范围。该配置不应再把同一流量送回原目标地区，必须核对底层绕行和反向分流，避免循环转发。目的 IPv6、网站可达性与服务访问条件需要另测。

本节描述后续部署方向。当前新增网关维护组件不自动创建反向出口，也不代表这条方向已经验收。
