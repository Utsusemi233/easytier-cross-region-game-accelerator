# 直连出口的低延迟与稳定性诊断

本页提供排查方法，不收录所有者的地址、身份或私人测量。直接接入与经访问端网关中转分别命名、分别验收。保留当前可用配置，新候选先隔离验证。

## 先确认正在测哪一层

| 检查 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 配置语法通过 | 字段可解析 | 每个传输协议都能运行 |
| 控制连接、peer、DHCP | 接入控制面在工作 | 应用TCP/UDP出网稳定 |
| 应用TCP与UDP出口一致 | 这些请求使用了目标出口 | 所有游戏流量都被接管 |
| 自有出口的回显 | 排除外部探测服务器后的隧道RTT | 游戏服务器RTT或载荷吞吐 |
| 连续业务与静默恢复 | 当前条件下连接可持续并恢复 | 其他热点、地址变动或完整开机恢复 |

核对核心真实版本和日志。若日志出现“unsupported client protocol upgrader”，先核查内置SDK的传输支持，不能继续通过延长等待或改DDNS掩盖兼容性失败。EasyTier原生核心与客户端内置SDK可能提供不同功能。[Mihomo EasyTier适配器](https://github.com/MetaCubeX/mihomo/blob/v1.19.32/adapter/outbound/easytier.go)

## 沿实际路径核对请求和回复

分别观察访问端LAN、访问端WAN、出口WAN。使用限时、限地址与限端口的报文头捕获，避免记录应用载荷。每次探测保留源端口、发起时间、接收期限与成功条件。

1. 请求出现在LAN却不在WAN：检查访问端分类、路由和转发。
2. 请求出现在访问端WAN却不在出口WAN：故障边界在两处捕获之间。
3. 出口已发回复，访问端WAN没有收到：检查反向路径，不直接认定是客户端分流错误。
4. 回复到达访问端WAN，LAN没有看到：核对访问端返程、连接跟踪和防火墙。

捕获的内核丢包、时钟差异、重复包和非对称路径也要记录。无时间同步时，不用两台设备的报文时间戳计算单向延迟。IPv6路由查询使用实际源地址；一个未指定源地址的失败查询不能替代真实回复路径。

## 保持连接与纠错分别比较

用同一UDP源端口持续发包，再与新连接比较。保持连接可能减少协商，但不能假定它会消除已有路径的丢失。静默测试注明是否仍有协议保活。

TCP承载可通过重传提高交付率，同时可能出现等待。比较相同目标的延迟分布、期限内交付和持续载荷；不要只展示一次最快应答。

UDPspeeder的FEC需要两端配套。其-i参数将一个纠错组的报文分散到指定毫秒时间窗，用于抵御突发丢失；-j是另外的模拟抖动选项。timeout、mode、MTU、FEC分组、分散时间逐项记录，保留未通过的组合。[UDPspeeder参数说明](https://github.com/wangyu-/UDPspeeder/blob/master/README.md)

比较同一数据量的线路字节和成功交付量。短包、超时提前组包、丢失及头部影响实际开销，理论分组比率不能代替测量。高冗余参数不能直接成为通用默认值。

**路由器上的纠错比较，不会给stock Clash自动增加UDPspeeder支持。** 新客户端要复用纠错网关，或使用能够配套该承载的实现；协议转换后重新验证实际路径。

## 记录与收尾

每轮单独保存：目标和假设、现场配置、实际命令、执行脚本摘要、逐次数据、失败、清理和未测试范围。后续修正写补充记录，保留原始证据。

只停止能核实归属的测试进程，删除自己的精确规则和临时文件。检查原生产配置摘要、服务与当前客户端状态。持续业务、恢复和应用测试未通过时，不将候选覆盖现用配置。

游戏最终按[验收方法](ACCEPTANCE.md)核对真实TUN、出口、双向数据与游戏内延迟；底层回显不能替代游戏验收。地址及网络恢复另见[移动接入](NETWORK-ROAMING.md)。
