# 网络和地址变化

恢复分成三件事：电脑的物理接口/网关变化、虚拟 DHCP 地址变化、出口的公网地址变化。这三者不能相互代替。

- 本机监测当前接口、物理 IPv4/IPv6、网关和 TUN IPv4；变化时先撤下自己的地区路线与旧入口，再更新有归属记录的底层绕行。
- 家庭端按当前 WAN 全球 IPv6 建立逐地址监听。地址签名变化只重启自己的纠错服务；Windows 从固定授权 ZeroTier 节点的近期活跃路径发现新公网入口。
- 公网 IPv6 不可用时尝试同一出口的授权 ZeroTier IPv4。可能发生中继和额外延迟；中继与出口是不同角色。
- 虚拟网关通过 ICMP，或家庭 DNS/TCP 加绑定虚拟源的 HTTPS 联合检查；地区路线还要求新鲜 HTTPS 验证。旧成功文件和物理 IPv6 网页访问不算出口验证。
- 所有入口失败时撤下项目地区路由，普通网络继续用物理出口。恢复后重新验证，不能仅看到进程就重新加路由。

参考配置每秒轮询电脑、每两秒轮询出口地址。DNS/HTTPS、连接重试和应用重连另需时间，这不是恢复总时间保证。保留当前已验证数据路径，避免发现器暂时不展示它就反复切线。

同一配置须测试 Wi-Fi→热点→Wi-Fi，记录 SSID、网关、物理 IP、端点和恢复用时。只有当前 Wi-Fi 能用不算不同网络验收。IPv6-only、认证页面、其他 VPN 或运营商前缀重新委派需单独测试。

健康验证会在有效期到期前尝试刷新。单次超时只在已有成功证明尚未过期时保留路线，状态显示降级；失败不能刷新成功时间。物理网络、虚拟地址或端点改变时清空旧证明。超过有效期仍未通过，就撤下项目地区路线，避免短探测抖动与过期假成功两种问题。
