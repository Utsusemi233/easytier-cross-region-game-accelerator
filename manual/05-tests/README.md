# 验收

每次部署保留时间、实际配置摘要、操作范围、结果文件和恢复读回。结果用 PASS、FAIL、SKIPPED；未测试不能写为通过。

| 检查 | 通过所需证据 |
| --- | --- |
| 配置和来源 | 官方来源、摘要、对应版本解析通过，未打印秘密 |
| 真正出口 | 当前虚拟网关 + 指定 TUN IPv4 源的 HTTPS；实际出口转发/NAT |
| 普通网络 | 未选目标的 IPv4 HTTPS、物理 IPv6、正常默认路由 |
| 单入口故障 | 临时阻断自己的新公网入口，认证私网备用通过主动验证 |
| 全部入口故障 | 地区路线撤销，普通网络仍可用，状态无过期成功 |
| 恢复 | 删除测试阻断，重新验证后恢复地区路线 |
| 客户端停启 | 官方 GUI 禁用后路线/自有纠错进程释放；运行后重新验证 |
| 换网 | 同配置使用不同 SSID/实际网关；离线撤销，重连恢复 |
| 远端地址变化 | 已有地址切换与真实运营商前缀变化分别记录 |
| 游戏或应用 | 进入实际场景，连接使用预期出口，记录同条件对照 |
| 生命周期 | 任务重启、防火墙重载、整机重启分别检查 |

故障注入只操作项目明确拥有的入口，须设自动删除/恢复期限并检查最终没有残留。不得断开整个 WAN 或停掉其他线路来代替局部测试。

本地隔离检查：`powershell -NoProfile -File tests/windows-roaming.ps1` 与 `tests/windows-direct-recovery.ps1`，以及 `node tests/check-source.mjs`。它们不改变真实网卡，不代替上述设备验收。个别 ping 丢包不直接等同出口失效，但 DNS 成功也不能独自替代 HTTPS。

公开手册给出方法和软件范围。具体家庭地址、设备标识、测试截图和私人性能记录保存在私人仓库。
